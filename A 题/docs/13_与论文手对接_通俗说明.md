# 给论文手的一份总说明(三问 + 建模思路 + 亮点,白话版)

> 目的:让不接触代码的论文写作者快速理解"我们做了什么、为什么这样做、能写什么"。
> 文中所有数字都来自最终结果,已由独立校验脚本复核,可直接写进论文。

## 一、题目在干什么(三句话)

- 一个基地(坐标 0,0)、一队同型号无人机:速度 55 km/h,8:00 同时起飞,干完自己的活回基地,不管续航。
- 有几十上百个巡检点,按重要程度分 I/II/III 级,分别要巡检 **3/2/1 次**,每次巡检在点上站 **5 分钟**。一个点要巡 3 次,就当 3 个"任务"看,可以由同一架或多架无人机完成。
- 三问一层比一层难:

| 问题 | 问什么 | 一句话理解 |
|---|---|---|
| 问题1 | 9 小时内干完所有活,**最少几架**?怎么分工走线,**总收工时间最短**? | 先定人手,再排班 |
| 问题2 | 在问题1 的人手数下,**每架干活时长尽量接近**,同时总收工时间仍要最短 | 排班要公平 |
| 问题3 | 天上多了**临时禁飞区**(每个=一个圆 + 一段生效时间),飞行、站桩巡检、空中等待都不得在生效时待在圆内 | 排班还要躲"会定时鼓起来的泡泡" |

## 二、每个问题我们怎么解的(大白话)

### 问题1:最少几架 + 最短收工

**第一步,算"至少要几架"(理论下界)。**
所有活的总工作量 = 巡检总时长(次数 × 5 分钟)+ 飞行时间。飞行时间有个躲不掉的下限:最远的点来回一趟要多久、N 架机每架至少要飞多少……把这些下限拼起来,除以 9 小时,得到"少于 N 架数学上不可能"。
**第二步,证明"这几架真的够"(构造)。**
让求解器真的排出 N 架的完整路线,验收 9 小时内完成。两边一夹:下界说不能更少,构造说这么多就够 → Nmin 成立。
**第三步,排路线(最短总收工)。**
把"最后一架无人机几点收工"当作目标,用工业级路径优化工具(OR-Tools)求解,多种子跑取最好。

- 结果:Nmin = 4 / 2 / 4 / 4(四个算例);最短收工 ≈ 7.88 / 7.18 / 8.37 / 8.02 小时。
- **诚实口径**:Case2 的"2 架"是严格证明的;Case1/3/4 的"4 架"是"构造出了 4 架方案 + 3 架反复搜不到 9 小时内解"的经验证据,论文里如实写。

### 问题2:先最短,再公平

两件事有先后:题目说"保证总收工尽量短**的同时**让各机时长接近",所以先顾总收工,再顾公平。做法:

- 给每架无人机规定"**至少要干 L 分钟**"。L 是一根旋钮:
  - L 拧大 → 活被逼着从"能者多劳"变成"平均分摊" → 各机时长越来越接近;
  - L 拧过头 → 总收工时间开始变长。
- 因为"L 可行 ⇒ 更小的 L 必可行"(单调),**二分搜索**几下就能找到"不伤害总收工时间的前提下能拧到的最大 L"。
- 另外报三档权衡:ε=0 / 1% / 2%(总收工最多放宽 0 / 1% / 2%),让读者看到"多牺牲多少时间能换多少公平"。

- 结果:四个算例的 δ(=最长机时长 − 最短机时长)从问题1 的 0.17 小时量级压到 **0.077 / 0.002 / 0.029 / 0.030 小时**,且总收工时间一点没变差(有的还更好)。
- **可写的理论点**:①单调性保证二分正确(可证);②δ 有一个数学下界(证书),Case2 的解**恰好顶到证书**,说明那个解在它自己的结构下公平性已达极限。

### 问题3:躲泡泡(全题最核心、最有写头)

**核心思想一句话:把"空间上的禁飞区"翻译成"出发时间的禁表"。**

1. 无人机直线匀速飞 → "走了百分之多少的路"和"过了百分之多少的时间"是同一个数;
2. 这条直线和禁飞圆求交(一道初中一元二次方程)→ 精确算出"几点几分进圆、几点几分出圆";
3. 和禁飞区的生效时间(比如 13:30–15:30)比一下 → 反推出"**几点出发必撞、几点出发没事**"——这就是该路段的**禁止出发时间段**;
4. 于是"别撞泡泡"从空间问题变成了查表问题。每条路(含返航)都有一张表,提前算好。

**撞上了怎么办?三种走法选最快:**
- 直飞(出发时刻不在禁表里);
- 等待(拖到禁飞结束再走);
- 绕行(贴着圆边擦过去,"切线–圆弧–切线"形状)。

**一个容易被忽略但很关键的点:等待本身也要躲泡泡。** 无人机站着等的位置如果自己就在生效的圆里,就不能原地等——要先挪到圆外去悬停。所以模型里"飞行、站桩巡检、空中等待"三类状态一视同仁地检查,一个都逃不掉。

**怎么排班(优化算法):**
- 先沿用问题2 的排班做修复(把撞泡泡的段换成等待/绕行);
- 再上 **ALNS(大邻域搜索)**:随机拆掉几个任务,再把每个任务试遍"插到哪架机、哪个位置"用**真实耗时**评估挑最好的插回去;配搬任务、换任务、倒序、跨机换尾等局部调整,模拟退火允许偶尔走坏步以免卡住。

**最值得写进论文的一句话(核心亮点):**
我们的搜索**每一步都用"真实动态耗时"评估**(把等待、绕行、禁飞全算进去),而不是"先用直线距离排一条最短路线,撞了泡泡再事后修补"。因为静态距离会骗人:基地旁边的点看着近,实际一去就得等禁飞结束,白白烧掉几小时;事后修补又没权力改任务顺序。用真实代价搜索,Case2 的收工时间从 11.92 小时压到 **10.97 小时**,Case3/4 在总收工不变的前提下把不公平度 δ 从 0.55/0.30 压到 **0.10/0.04**。

**三道保险:**
- 飞行段逐段验证;站桩 5 分钟验证;空中等待的位置 × 时间验证;
- 验证程序与求解程序**独立编写**,全部算例违例数 = 0。

## 四、可以拿出来讲的亮点(按推荐顺序)

1. **统一时空硬约束模型(问题3)**:空间禁飞区 + 生效时间段合成一个"会鼓起来的泡泡";无人机飞行、巡检、等待三类状态用同一个判据管住;用解析求交把空间约束精确翻译成"出发时间禁表"——不采样、无误差、可查表。
2. **"真实动态代价上搜索"而非"静态求解+事后修复"**:有对照实验数据(Case2 11.92→10.97 h;Case3 δ 0.55→0.10;Case4 δ 0.30→0.04),是全文最有说服力的一段。
3. **问题2 的二分法有理论味**:可行域单调(可证)、迭代次数有公式、δ 有数学下界证书且 Case2 达到紧界。
4. **证据链完整**:每个数字都能复现;求解与验证独立;全部零违例;敏感性分析六项(速度、服务时长、禁飞半径、零长度窗口解读、强制间隔、任务增减)。
5. **诚实声明**(在竞赛里是加分项):求解器给的是"找到的最好方案"而非全局最优;多圆同时绕行未求全局最短;这些在局限里明说。

## 五、不能乱说的话(诚实边界)

- "最短收工时间"应表述为"**求解器在设定时限内找到的最好可行解**(上界)",不要说"最优解",除非是 Case2 的 Nmin=2(严格证明)。
- 问题1 的 Nmin:Case2 严格得证;Case1/3/4 表述为"下界+构造+N−1 架反复求解不可行的经验证据"。
- 问题2 的 δ:是"ε 层内、相对搜索网格的最好值"。
- 问题3 假设:直线飞行、匀速、开圆约定(擦边不算进)、多次巡检可连续(敏感性 S5 讨论过放宽的代价)。
- 问题3 语义口径:采用严格版(不在生效圆内等待,必要时圆外悬停);旧宽松版结果在 docs/06 有对比,论文正文按严格版写即可。

## 七、给论文手的写作路线建议

1. 摘要按"**问题 → 模型一句话 → 方法一句话 → 结果一个数 → 验证一句**"写;
2. 每问一个固定结构:**建模(大白话+少量公式)→ 算法(为什么这样设计)→ 结果(表+图)→ 验证(独立复核)**;
3. 三问之间的递进关系写清楚:问题1 打底(人手+最短),问题2 加"公平",问题3 加"禁飞",后一问的初解都来自前一问——这就是"逐层构建"的叙事线;
4. 问题3 多花篇幅:它是全文模型最重、创新点最多的一问,建议占建模章节的 40% 以上。
