# 问题2 二分法原理与计算过程详解

> 对应代码 `src/p2_bin.py`;全部数字来自真实求解日志 `A 题/output/p2bin_Case*.log` 与结果 `p2_*.json`。本文档可直接改写为论文 4.2 节。

---

## 0. 一句话概括

问题2 的第二目标"最小化 δ=T_max−T_min"被等价转化为**单参数可行性问题**:找最大的工作时长下界 L*,使"每台机工作时长 ≥ L 且总完成时间 ≤ T*(1+ε)"仍有可行调度。可行域关于 L 单调,因此用**二分搜索**求 L*,收敛到 2 min 容差内只需 ≈8 次求解。

## 1. 问题化简:从双目标到单参数判定

### 1.1 原始目标

第一层(问题1):T* = min T_max。
第二层(问题2):在 T_max ≤ T*(1+ε) 内,min δ,δ = T_max − T_min。

### 1.2 关键变换:引入下界 L

对每个无人机 r 施加约束 end_r ≥ L。记判定问题:

$$\mathcal{P}_\varepsilon(L):\quad \text{是否存在调度,使}\ \forall r:\ end_r\ge L,\ \text{且}\ T_{max}\le T^*(1+\varepsilon)\ ?$$

若 𝒫_ε(L) 可行,其任一可行解满足:

$$T_{min}\ge L \ \Rightarrow\ \delta = T_{max}-T_{min} \le T^*(1+\varepsilon) - L$$

即:**L 越大,δ 的上界越紧**。因此第二层目标 min δ 转化为:

$$L^*(\varepsilon) = \sup\{\, L : \mathcal{P}_\varepsilon(L)\ \text{可行} \,\}$$

实际求解时不用"可行性判定",而用更简单的 **oracle**:直接解"min T_max s.t. end_r ≥ L"(OR-Tools 一次调用),拿到解后检查 T_max ≤ T*(1+ε)。若 oracle 返回的 span 超限或不可行,判定 𝒫_ε(L) 不可行。

## 2. 二分法成立的原理:单调性

### 2.1 单调性引理(命题1)

> **若 𝒫_ε(L) 可行,则对任意 L′ ≤ L,𝒫_ε(L′) 可行。**

**证明**:𝒫_ε(L) 的可行调度同时满足"所有机 ≥ L ≥ L′"与"T_max ≤ T*(1+ε)",故同一调度就是 𝒫_ε(L′) 的可行解。∎

**推论**:𝒫_ε 的可行 L 集合是**区间** [0, L*(ε)](左闭)。这就是二分法的全部依据——**可行域随 L 单调收缩,且收缩是"从下往上一条边界"**,不是散布的可行/不可行交替,故可以用二分定位边界 L*(ε)。

### 2.2 与"直接网格搜索"的本质区别

| | 粗网格(旧版) | 二分(新版) |
|---|---|---|
| 探针位置 | 0, 30, 60, …, T*(共 ≈16 个) | 每次取区间中点,自适应 |
| 精度 | ±15 min | ±2 min(容差 TOL=120 s) |
| 调用次数 | O(T*/30min) | O(log₂(T*/TOL)) |
| 单调性利用 | 无 | 完整利用 |

## 3. 算法与不变量(算法1:LEX-BALANCE 的二分部分)

```
输入: T*, ε, 容差 TOL;oracle(L) 返回 (span, 调度) 或"无解"
cap ← T*(1+ε);  hi ← cap + TOL
lo ← 0                             # 不变量:𝒫_ε(lo) 可行(由问题1 解保证)
if oracle(hi) 可行: 返回 hi        # 病理情形:全域可行
while hi − lo > TOL:
    L ← (lo + hi) / 2              # 中点
    if oracle(L).span ≤ cap + 1s:  lo ← L
    else:                          hi ← L
# 噪声修复:边界上方再探 1~2 步(启发式 oracle 的误判容错)
for k = 1, 2:
    if oracle(lo + k·TOL).span ≤ cap + 1s:  lo ← lo + k·TOL
    else: break
返回 lo
```

### 3.1 循环不变量(命题2)

每轮循环保持:

1. **lo 端可行**:oracle(lo) 曾返回 span ≤ cap;
2. **hi 端不可行**:oracle(hi) 曾返回 span > cap 或无解;
3. **边界夹在中间**:L*(ε) ∈ (lo, hi](精确 oracle 意义下)。

**证明**:归纳。初始 lo=0 可行(问题1 的解即 𝒫_ε(0) 的可行证);hi=cap+TOL 必不可行(若可行则 span ≥ min end ≥ L = hi > cap,矛盾——注意这是**纯数学矛盾,与 oracle 无关**)。每轮中点判定后更新其一,不变量保持。∎

### 3.2 迭代次数(命题3)

区间初始宽 hi−lo = cap+TOL ≈ 30 000 s;每轮减半,经 k 轮后宽 ≈ (cap+TOL)/2ᵏ。终止条件 ≤ TOL,故

$$k \le \left\lceil \log_2\frac{cap+TOL}{TOL} \right\rceil = \lceil \log_2 242 \rceil = 8$$

**8 次 oracle 调用把 8.4 小时的搜索区间压缩到 2 分钟**——这就是二分相对网格的根本优势。

## 4. 正确性边界:精确 oracle 与启发式 oracle

### 4.1 精确 oracle 下的正确性(命题4)

若 oracle(L) 精确返回 min T_max(L),则算法返回 L̂ 满足 L* − TOL ≤ L̂ ≤ L*,即 L* 的 TOL-近似。

### 4.2 实际 oracle 是 GLS 启发式:两类实测噪声

oracle 用 OR-Tools GLS(2 种子 × 30 s)近似求解 min T_max,**不是精确的**。真实日志里两类噪声都有:

**噪声A:span 非单调。** span(L) 理论上随 L 非降,实测出现反例:
- Case2:probe(L=0)=7.194 h > probe(L=108.2 min)=7.186 h;
- Case3:probe(L=126.1 min)=8.772 h > probe(L=63.0 min)=8.368 h。

原因:L=0 时约束松、解空间大,GLS 30 s 内没找到和带约束时一样好的解——启发式搜索路径随约束而变。

**噪声B:"无解"≠不可行。** 求解器时间受限,返回 None 只是"没找到",不是数学上不可行(例:Case2 ε=0 层几乎所有探针都被判不可行,但候选池里 L=122.4 min 的解 span=7.125 h 完全合法)。

**噪声C:初始端假设被破坏。** Case4 ε=0 层 probe(0)=8.053 h > T*=8.020 h,连"lo=0 可行"都不成立;Case2 同理。二分仍能收敛,但依赖下述防护兜底。

### 4.3 三项工程防护(对应 p2_bin.py)

1. **多种子取优**:每个探针跑 2 个 CP-SAT 随机种子,取 span 小者,压噪声A;
2. **边界噪声修复**:收敛后在 lo 上方 TOL、2·TOL 处补探,修复"单步误判不可行"把真边界排除掉的风险;
3. **全候选池选优(最关键)**:二分只负责"生成探针 + 定位边界",**层内最终解不取 lo 本身,而在全部探针(含问题1 原解)里按 (T_max, δ) 词典序取最优**。这样即使二分边界定位被噪声带偏(如 Case2 收敛到 L*=0),候选池里更优的解(L=122.4 min 的 7.125 h/0.002 h)依然被选中。

### 5.4 实测非单调案例(Case4):L*(ε=1%) < L*(ε=0%)

理论上 L*(ε) 随 ε 非降(可行域扩大),实测 Case4 出现 L*(1%)=196.3 < L*(0%)=207.6。原因:两个 ε 层的二分路径不同、探针集合不同;oracle 噪声(span 非单调)使 ε=0 层在 L=203.8/207.6 判"可行"(span=8.000 ≤ 8.020),而 ε=1% 层在 L=198.2 判"不可行"(span=8.229 > 8.100),而 L=194.4 处找到了 span=7.804 的好解。**这正是 4.2 节噪声A 的直接证据**,也是必须"候选池选优 + 如实报告 L* 为启发式估计"的原因。

### 5.5 噪声但结果更优的案例(Case2)

Case2 ε=0 层:probe(0)=7.194 > cap,二分一路判不可行,收敛到 L*=0(错误边界)。但 ε=2% 层的二分路径探到 L=122.4 min → span=7.125 h、δ=0.002 h(6 秒),该解对所有 ε 层都可行且全局最优,被候选池选中。结论:**即使边界定位被噪声完全带偏,防护 3 仍保证最终结果正确**。

## 6. ε 分层与 Pareto 剖面

### 6.1 理论关系

δ*(ε) := min{δ : T_max ≤ T*(1+ε)} ≤ T*(1+ε) − L*(ε),且 ε 越大,cap 越松,L*(ε) 非降、δ*(ε) 非增(理论趋势)。

### 6.2 实测剖面(本实例三层选到同一解)

| 算例 | ε=0 | ε=1% | ε=2% | 解释 |
|---|---|---|---|---|
| Case1 | 7.840/0.077 | 同 | 同 | 候选池中 span 最小者(7.840)已远低于 T*,ε 约束不紧 |
| Case2 | 7.125/0.002 | 同 | 同 | 同上 |
| Case3 | 8.368/0.029 | 同 | 同 | 同上 |
| Case4 | 7.804/0.030 | 同 | 同 | 同上 |

按 (T_max, δ) 词典序选优时,若找到的 span 最小值已低于 T*,则三个 ε 层自然重合。**论文应如实呈现该表并说明原因**,而非编造差异化的剖面。

## 7. 解质量证书:δ 的不可改进下界

### 7.1 引理(命题5)

对任意调度(总工时 S = Σ_r end_r,机数 N):

$$\delta \ge \frac{N\cdot T_{max} - S}{N-1}$$

**证明**:除最长机外,N−1 台机的时长均 ≥ T_min,故
S = T_max + Σ_{r≠最长} end_r ≥ T_max + (N−1)·T_min,移项得 T_max − T_min ≥ (N·T_max − S)/(N−1)。∎

含义:**给定该解的总工时 S 与 makespan,δ 有一个不可逾越的下界**;若实际 δ 接近该界,说明在不改变"总飞行量/总工时"的前提下,均衡已做到极限,继续压缩 δ 只能靠重构分组。

### 7.2 四个算例的证书值(由最终解计算)

| 算例 | N | T_max (h) | 证书下界 (h) | 实际 δ (h) | 间隙 (h) |
|---|---|---|---|---|---|
| Case1 | 4 | 7.8403 | 0.0426 | 0.0769 | 0.0344 |
| Case2 | 2 | 7.1247 | **0.0017** | 0.0017 | **0(紧界!)** |
| Case3 | 4 | 8.3683 | 0.0178 | 0.0294 | 0.0117 |
| Case4 | 4 | 7.8039 | 0.0209 | 0.0300 | 0.0091 |

**Case2 的证书是紧的**:δ=0.0017 h 恰好等于理论下界,证明该解在其 (S, T_max) 下已达最优均衡——论文中可作"最优性证据"的一个亮点(注:这是相对该 S/T_max 的条件最优,不是全局最优)。

## 8. 复杂度与效率

- **每次 oracle 调用**:OR-Tools GLS,2 种子 × 30 s ≈ 60 s(限时);
- **每 ε 层**:≤ 8 次二分 + ≤2 次噪声修复 ≈ 10 次;
- **三 ε 层**:≈ 31 次/算例(探针跨层有少量重复;三层 hi₀ 不同导致缓存复用有限);
